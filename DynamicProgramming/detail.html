1. Your base: Complete / Unbounded Knapsack (2D)

Your template (slightly cleaned):

// Unbounded (complete) knapsack - 2D DP
int knapsack_unbounded(const vector& wt, const vector& val, int W, int n) {
  vector> dp(n+1, vector(W+1, 0));
  for (int i = 1; i <= n; ++i) {
    for (int w = 1; w <= W; ++w) {
      if (wt[i-1] <= w) {
        // Use item i-1 any number of times -> dp[i][w - wt[i-1]] (stay on same i)
        dp[i][w] = max(val[i-1] + dp[i][w - wt[i-1]], dp[i-1][w]);
      } else {
        dp[i][w] = dp[i-1][w];
      }
    }
  }
  return dp[n][W];
}
Why dp[i][w - wt] (not dp[i-1])? Because when you pick item i-1 in an unbounded problem you can pick it again — so you allow transitions from the same item row i.

2. 0/1 Knapsack (bounded: each item at most once)

Change the recurrence: when you pick item i-1, you must come from i-1 (cannot reuse the same item).

// 0/1 knapsack - 2D DP
dp[i][w] = max(dp[i-1][w], val[i-1] + dp[i-1][w - wt[i-1]]);
// In code:
if (wt[i-1] <= w) dp[i][w] = max(val[i-1] + dp[i-1][w - wt[i-1]], dp[i-1][w]);
else dp[i][w] = dp[i-1][w];

1D optimization (common pattern): iterate capacity from high to low.

// 0/1 knapsack - 1D DP
vector dp(W+1, 0);
for (int i = 0; i < n; ++i) {
  for (int w = W; w >= wt[i]; --w) {
    dp[w] = max(dp[w], dp[w - wt[i]] + val[i]);
  }
}

3. Unbounded (1D) — space optimized

// Unbounded knapsack - 1D DP (capacity ascending)
vector dp(W+1, 0);
for (int i = 0; i < n; ++i) {
  for (int w = wt[i]; w <= W; ++w) {           // ascending -> allow reuse
    dp[w] = max(dp[w], dp[w - wt[i]] + val[i]);
  }
}
Important: for unbounded 1D, iterate w ascending; for 0/1 1D, iterate w descending.

4. Bounded knapsack (each item has limited count)

Three standard ways:

  1. Simple loop — if counts small: repeat item count times and treat as separate 0/1 items (costly).
  2. Binary splitting / binary decomposition — convert count into powers of two (efficient).
  3. Use DP with inner loops (O(nW·count)) — sometimes OK.
// Example: binary splitting (1D dp)
for each item i with count c:
  int k = 1;
  while (c > 0) {
    int take = min(k, c);
    // item of weight = wt[i]*take, value = val[i]*take, single 0/1 item now
    for (int w = W; w >= wt[i]*take; --w)
      dp[w] = max(dp[w], dp[w - wt[i]*take] + val[i]*take);
    c -= take;
    k <<= 1;
  }

5. Counting ways vs maximizing value (use + vs max vs ||)

  • Maximization problems (typical knapsack): use max().
  • Counting solutions (how many ways to achieve weight W): use dp[w] += dp[w - wt] and initialize dp[0]=1. Order of loops matters (unbounded: w ascending).
  • Feasibility / subset-sum (boolean): use logical OR: dp[i][w] = dp[i-1][w] || dp[i-1][w-wt] or 1D with descending order.
  • Minimization (min coins to make W): use min() and initialize with INF.
// Counting ways (unbounded coin-change style, 1D)
vector dp(W+1, 0);
dp[0] = 1;
for (int i = 0; i < n; ++i)
  for (int w = wt[i]; w <= W; ++w)
    dp[w] += dp[w - wt[i]];   // addition, not max

// Feasibility (subset-sum) - boolean
vector dp(W+1, 0);
dp[0] = 1;
for (int i = 0; i < n; ++i)
  for (int w = W; w >= wt[i]; --w)
    dp[w] = dp[w] || dp[w - wt[i]];

6. Value-based DP (optimize by value instead of weight)

Use when sum(values) is smaller than W. Typical for "min weight to achieve at least value V".

// dp[v] = minimum weight to achieve value v
const int INF = 1e9;
int Vsum = accumulate(val.begin(), val.end(), 0);
vector dpV(Vsum+1, INF);
dpV[0] = 0;
for (int i = 0; i < n; ++i)
  for (int v = Vsum; v >= val[i]; --v)
    dpV[v] = min(dpV[v], dpV[v - val[i]] + wt[i]);

7. Reconstructing chosen items

Keep a parent pointer or boolean chosen table. For 2D dp it's straightforward — backtrack from dp[n][W]. For 1D dp, keep extra array take[i][w] or store previous weight index.

9. Multi-dimensional / multi-constraint knapsack

When items have two costs (e.g., weight and volume) you need dp with extra dimension dp[w][v] or compress appropriately. Complexity increases multiplicatively.

10. Monotonic queue optimization / optimization tricks

Used to speed up bounded/unbounded knapsack transitions to O(nW) with small constant or improved complexity for large counts. Usually applied to the recurrence that resembles a sliding window. Search for "Monotonic queue optimization knapsack" when needed.

12. Explanation for "sometimes + in if condition, something ||, sometimes max"

You're seeing these because different problem statements ask different questions:

  • Do you need the best value? -> use max().
  • Do you need whether a weight is reachable? -> use logical || (or booleans).
  • Do you need number of ways? -> use + (accumulate counts).
  • Do you need minimum number of items / weight? -> use min() and INF initialization.

13. Complete set of small template changes from your original snippet

  1. For 0/1 (2D): change dp[i][w - wt[i-1]] to dp[i-1][w - wt[i-1]].
  2. For boolean feasibility: replace = max(...) with = dp[i-1][w] || dp[i-1][w-wt] (or 1D variant with || and descending w).
  3. For counting ways: use numeric type (long long), initialize dp[0]=1, and use += in transitions.
  4. For bounded (count c): binary-split counts into powers of two and treat as multiple 0/1 items (or use monotonic queue).
  5. For minimization: initialize dp to INF and use min() transitions.
  6. Loop orders: when using 1D always pick loop order to reflect reuse semantics: ascending -> reuse allowed, descending -> no reuse.

14. Short annotated checklist for converting your template

  • Do you want multiple uses of the same item? —> unbounded: use dp[i][w - wt] (or 1D ascending).
  • At most once? —> 0/1: use dp[i-1][...] and 1D descending.
  • Counting vs maximizing? —> replace max with + or || as required.
  • Bounded with large counts? —> binary-split or monotonic queue.
